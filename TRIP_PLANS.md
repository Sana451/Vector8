# Поездки (trip plans): уточнённый маршрут, водитель, экспорт

Документ описывает реализованный план: как результат оптимизатора превращается в
сохранённую поездку, как HERE строит по ней реальный маршрут, как поездка
назначается водителю и как её проверить руками (UI и Swagger).
Техническая справка по модулю — `backend/app/trip_plans/README.md`.

## 1. Идея

Оптимизатор выбирает заправки и оценивает объезды приблизительно. Поездка
замораживает этот результат и отправляет выбранные заправки в HERE как
промежуточные точки (`via`), чтобы получить **реальный** маршрут с настоящими
заездами. Уточнённый маршрут рисуется отдельным слоем поверх карты — его можно
визуально сверить с оптимизатором. Сохранённую поездку диспетчер назначает
водителю, а тот открывает её, экспортирует в навигатор или смотрит по
публичной ссылке.

## 2. Что реализовано

| Фаза | Содержание |
|------|-----------|
| 1. Бэкенд | таблица `trip_plans` (миграция), модуль `app/trip_plans`, поддержка `via` в HERE (`waypoints` + `waypoint_stop_duration_seconds`), создание и пересчёт поездки |
| 2. Карта | кнопка «Refine route via stops», независимый слой уточнённого маршрута, сравнение расстояния и времени с планом |
| 3. Роли | `UserRole` (admin / dispatcher / driver), `driver_profiles`, назначение, статусы, страницы Trips и My Trips |
| 4. Экспорт | GPX / KML / CSV, ссылки Google Maps и HERE WeGo, карта поездки для водителя |
| 5. Тесты, share | публичная ссылка по токену, тесты, документация |

### Жизненный цикл

`draft` → `refined` / `refine_failed` → `assigned` → `in_progress` → `completed`
(или `cancelled`). Вернуться в `draft` нельзя; снятие водителя откатывает статус
к `refined` / `refine_failed` / `draft`.

### Роли

| Роль | Видит | Может |
|------|-------|-------|
| admin / superuser | все поездки | всё |
| dispatcher (по умолчанию у новых пользователей) | свои поездки | создавать, пересчитывать, назначать, менять статус, удалять, публиковать ссылку |
| driver | только назначенные ему | ставить `in_progress` / `completed`, экспорт |

### API (`/api/v1`)

| Метод | Путь | Роль | Назначение |
|-------|------|------|-----------|
| POST | `/trip-plans/` | диспетчер | создать из `optimization_run_id` и сразу уточнить |
| GET | `/trip-plans/` | диспетчер | список своих (админ — все) |
| GET | `/trip-plans/my` | водитель | назначенные мне |
| GET | `/trip-plans/{id}` | по доступу | детали: стопы, геометрии, дельта, `is_shared` |
| POST | `/trip-plans/{id}/refine` | диспетчер | пересчитать маршрут (`force_refresh`, `provider`, `stop_duration_minutes`) |
| POST | `/trip-plans/{id}/assign` | диспетчер | `{"driver_id": "<uuid>"}` или `null` для снятия |
| PATCH | `/trip-plans/{id}/status` | по роли | сменить статус |
| GET | `/trip-plans/{id}/export.{gpx\|kml\|csv}` | по доступу | скачать файл |
| POST | `/trip-plans/{id}/share` | диспетчер | `{"enabled": true}` — выдать, `false` — отозвать |
| GET | `/trip-plans/shared/{token}` | без авторизации | публичный просмотр |
| DELETE | `/trip-plans/{id}` | диспетчер | удалить |
| GET | `/drivers/` | диспетчер | список водителей для назначения |
| GET/PUT | `/drivers/me/profile` | водитель | свой профиль |
| PUT | `/drivers/{user_id}/profile` | диспетчер | профиль водителя |

### Экспорт и навигаторы

- GPX/KML/CSV строятся на сервере (`export.py`); трек прореживается до 2000 точек.
- Старт и финиш маршрута добавляются в `stops` (`kind=start` / `kind=destination`) при каждом ответе и экспорте, берутся из геометрии. Подписи — `origin_label` / `destination_label`, для старых маршрутов «Start» / «Destination».
- Ссылки Google Maps делятся на участки по 8 точек с перекрытием в одну; есть ссылка HERE WeGo (`frontend/src/lib/navigatorLinks.ts`).

### Публичная ссылка

Токен — `secrets.token_urlsafe(32)`. Повторная выдача возвращает тот же токен,
отзыв обнуляет его навсегда (старая ссылка даёт 404). Публичный ответ не содержит
id владельца, водителя и машины; API деталей отдаёт только флаг `is_shared`.
Страница: `/trip/<token>`, вне авторизованного layout.

### Тесты

`cd backend && uv run pytest -q tests/trip_plans` — правила доступа, экспорт,
API (роли, назначение, статусы, экспорт, share, удаление), создание и
пересчёт с поддельным провайдером. Фронтенд: `bun run test` / `vitest run`
(`navigatorLinks`, форматтеры `lib/tripPlans`).
Для тестовой БД `app_test` нужен `alembic upgrade head`.

## 3. Подготовка к проверке

1. Поднять окружение (см. `development.md`): БД с миграциями (`alembic upgrade head`), бэкенд и фронтенд. В `.env` должен быть ключ HERE, иначе уточнение завершится `refine_failed`.
2. Адреса по умолчанию: фронтенд — адрес из `development.md`, Swagger — `http://localhost:8000/docs` (префикс API `/api/v1`).
3. Нужны три учётки. Админ — `FIRST_SUPERUSER` из `.env`.
   - **Диспетчер**: зарегистрироваться на `/signup` (роль по умолчанию — dispatcher) либо создать через Swagger.
   - **Водитель**: под админом открыть **Admin** → **Add User** (поле **Role** = Driver) или у существующего пользователя **Edit User** → **Role**. Через Swagger: `POST /api/v1/users/` с телом
     `{"email": "driver@example.com", "password": "changethis123", "role": "driver"}` либо `PATCH /api/v1/users/{id}` с `{"role": "driver"}`.
4. Опционально заполнить профиль водителя: `PUT /api/v1/drivers/{user_id}/profile` под диспетчером.

### Авторизация в Swagger

`POST /api/v1/login/access-token` (username = email, password) → скопировать
`access_token` → кнопка **Authorize** вверху страницы → вставить токен.
Для смены роли выйти (Authorize → Logout) и авторизоваться заново.

## 4. Проверка от лица диспетчера

### Через UI

1. Войти диспетчером. В меню должен быть пункт **Trips**, пункта **My Trips** нет.
2. Открыть **Map**, задать маршрут (откуда/куда), выбрать машину и запустить оптимизатор — появятся заправки.
3. Нажать **Refine route via stops**. Ожидаем: на карте отдельный слой уточнённого маршрута, заезды в выбранные заправки, блок со сравнением расстояния и времени «план vs уточнённый». Если провайдер вернул ошибку — виден текст ошибки, кнопка меняется на повторный пересчёт.
4. Нажать **Recalculate refined route** — маршрут пересчитывается.
5. Открыть **Trips** — поездка в списке со статусом `Refined`. Открыть её: сводка (дистанция, время, дельта, число остановок), карта, таблица остановок.
6. Карточка **Assignment**: выбрать водителя → **Save**. Статус станет `Assigned`. Выбрать «No driver» → **Save** — снимется, статус откатится.
7. Блок действий: скачать GPX / KML / CSV, открыть ссылки Google Maps / HERE WeGo.
8. Карточка **Public link**: **Create link** — ссылка скопируется в буфер. Открыть её в приватном окне (без входа) — страница `/trip/<token>` показывает карту и остановки. **Revoke** — ссылка перестаёт работать («Trip not available»).
9. Диспетчер не должен попадать на `/my-trips` (перенаправление на Trips).

### Через Swagger (под диспетчером)

1. `POST /api/v1/fuel-optimization/calculate` — получить результат, в ответе взять id запуска оптимизации (`optimization_run_id`; в UI он уходит в кнопку Refine автоматически).
2. `POST /api/v1/trip-plans/` — `{"optimization_run_id": "<uuid>", "name": "Test run", "stop_duration_minutes": 10}` → 201, `status` = `refined`, есть `refined_geometry`, `delta`. При ошибке HERE ответ всё равно 201, но `status` = `refine_failed` и заполнен `refine_error`.
3. `GET /api/v1/trip-plans/` и `GET /api/v1/trip-plans/{id}` — поездка в списке, в деталях стопы и геометрии.
4. `POST /api/v1/trip-plans/{id}/refine` — `{"force_refresh": true}`.
5. `GET /api/v1/drivers/` — найти `id` водителя.
6. `POST /api/v1/trip-plans/{id}/assign` — `{"driver_id": "<uuid>"}` → `status` = `assigned`; затем `{"driver_id": null}` — снятие.
7. `GET /api/v1/trip-plans/{id}/export.gpx` (и `kml`, `csv`) — файл с заголовком `Content-Disposition`.
8. `POST /api/v1/trip-plans/{id}/share` — `{"enabled": true}` → `share_token`. Затем **без авторизации** (Authorize → Logout) `GET /api/v1/trip-plans/shared/{token}` → 200 без `id`, `owner_id`, `assigned_driver_id`. Снова с токеном: `{"enabled": false}`, после чего `GET /shared/{token}` → 404.
9. Негативные проверки: `GET /api/v1/trip-plans/my` под диспетчером → 403; поездка другого диспетчера → 403; `PATCH .../status` со статусом `draft` → 400.
10. `DELETE /api/v1/trip-plans/{id}` — удаление (повторный GET → 404).

## 5. Проверка от лица водителя

Предварительно диспетчер создал поездку и назначил её этому водителю (раздел 4).

### Через UI

1. Войти водителем. В меню пункт **My Trips**, пункта **Trips** нет; открытие `/trips` перенаправляет на My Trips.
2. **My Trips** — только назначенные поездки. Чужие и неназначенные не видны.
3. Открыть поездку: карта с уточнённым маршрутом и заправками, список остановок, дистанция и время.
4. Блок действий: GPX / KML / CSV скачиваются; Google Maps / HERE WeGo открывают маршрут в навигаторе.
5. Кнопки статуса: **Start trip** (→ `In progress`), затем **Mark completed**. Другие статусы водителю недоступны.
6. Прямой переход по id чужой поездки (`/my-trips/<id>`) — ошибка доступа.

### Через Swagger (под водителем)

1. Авторизоваться водителем (раздел 3).
2. `GET /api/v1/trip-plans/my` — список назначенных поездок.
3. `GET /api/v1/trip-plans/{id}` — детали назначенной поездки → 200; чужой → 403.
4. `PATCH /api/v1/trip-plans/{id}/status` — `{"status": "in_progress"}` → 200, затем `{"status": "completed"}`.
5. Запрещённое: `{"status": "cancelled"}` → 400 (водитель ставит только `in_progress`/`completed`).
6. `GET /api/v1/trip-plans/{id}/export.gpx` — скачивается.
7. Запрещённое: `POST /api/v1/trip-plans/`, `/refine`, `/assign`, `/share`, `DELETE`, `GET /api/v1/trip-plans/` → 403.
8. `GET /api/v1/drivers/me/profile` и `PUT /api/v1/drivers/me/profile` — свой профиль.

## 6. Известные ограничения

- Число `via`-точек ограничено HERE; при превышении — `refine_failed` с текстом ошибки.
- Роль меняется только суперпользователем (Admin → Edit User); пользователь сам себе роль изменить не может. Права админки по-прежнему определяет `is_superuser`, а не роль.
- Автоматических UI-тестов для страниц и компонентов поездок нет; покрыты чистые функции и API.
- Новых переменных окружения модуль не вводит; нужен только ключ HERE и миграции (`alembic upgrade head`, для тестов — также в `app_test`).
